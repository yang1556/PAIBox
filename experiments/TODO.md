## 与 `quantize` 分支的关系(2026-09-17 勘查)

仓库里另有一条独立的量化实现:分支 `quantize`,包 `paibox/quantize_tools/`,
含 CIFAR-10 的 CNN 与 ResNet 例子。我们的工作在 `feat/quant-frontend`
(`paibox/quant/` + `tests/quant/`,已提交)。两者能力互补得相当整齐。

**他们更强的**

| 能力 | 做法 |
| --- | --- |
| 非对称量化(zp≠0) | 4 项分解 $Op(X_q{-}Z_x, W_q{-}Z_w)$ 展开成四项:Term1 正常核;Term2 沿归约轴求和×$Z_w$,占一核+多播;Term3/4 是编译期常数,折进加法泄露。代价 $w{+}1$ 神经元、2 核 |
| 残差 | 已打通到 PAIIR。见下"可直接复用" |
| 算子融合 | `torch.ao` 原生,覆盖 conv+bn(+relu)、linear+bn(+relu)、以及 `relu(add(...))` 四种朝向 |
| 仿真 | 手写 `Manual*` 算子精确复现 4 项计算与 LUT |
| 实例 | ResNet-CIFAR10,含精度对比 |

**我们更强的**

| 能力 | 我们 | 他们 |
| --- | --- | --- |
| 位宽 | $\{1,2,4,8\}$ | **只有 8-bit**(`DTypeConfig` 与两个 observer 写死 `torch.qint8`) |
| 粒度 | per-channel + 2 幂策略 + `Pow2MseCalibrator` | **只有 per-tensor**(`qscheme=per_tensor_symmetric` 写死) |
| 标定 | MSE / percentile / 2 幂格点搜索 | **只有 `MinMaxObserver`** —— 即 2-bit 崩到 19.5% 的那个方法 |
| LUT | 阈值置于判决边界,无系统偏差;支持非均匀格点 | 均匀网格 + 截断,**半个 LSB 系统偏差**(§7.6) |
| 约束检查 | C1–C12,报错含"违反哪条 + 为什么 + 最近替代" | 仅 5 处类型检查,无硬件约束 |
| 前后端契约 | `QuantSpec`,声明式、硬件无关 | 无中间表示,FX 图直出 `Manual*` |
| SNN | `SnnActivation` + IF/LIF 换算 | 无(grep 无命中) |
| 代价模型 | `cost_model.md` | 无 |

**决策:以 quant_tool 为基座,不改用 torch.ao。** 理由是 SNN ——
`BackendConfig` 只能描述融合模式与 dtype,**没有任何位置能表达"这一层改成 SNN、
阈值 θ、时间步 T"**。这与"ONNX Q/DQ 表达不了这颗芯片的决策"是同一条论证:
交换格式必须能承载目标的决策空间,而 mode × 位宽 × 粒度这个空间 torch.ao 装不下。
另一个硬理由:他们只有 8-bit + per-tensor + MinMax,而这一个点上精度与资源都没有
可优化的维度,论文的立论无从展开。

**可直接复用(与前端无关)**

`QuantizedConvAddReLU2dOp`(`paibox/paiir/ir/quantized_ops.py:88`)是普通 PAIIR 节点,
契约只有 `conv` / `act` / `shortcut_m` / `shortcut_n` 四个字段;
`quantized_materialize.py` 只按 `isinstance` 触发,不依赖 `Manual*` 或 torch.ao。
所以残差我们**不需要复刻 torch.ao 的模式识别**,只需在 `export` 里产出该节点并算出
$M, n$。三核展开(卷积出膜电位 / shortcut 的 $M{\cdot}2^n$ 缩放出膜电位 / 膜电位累加+LUT)
由 PAIBox 侧的 pass 负责。

**要吸收的洞见:$M \times 2^n$ 不是纯 2 的幂。** shortcut 对齐需要
$\text{Ratio} = s_x/s_{\text{accum}}$,他们用一个 8 位权重 $M$(填进 depthwise 1×1 卷积)
加乘法泄露 $2^n$ 去逼近,等于手工搭出 8 位尾数的浮点。精度差别很大:纯 2 的幂最坏
偏差 41.4%($\sqrt2-1$,与实测 `pc-round` 的 38.9–41.4% 吻合),$M\times 2^n$ 最坏约
**0.39%**,细约 100 倍。

这**不能直接搬到 per-channel**($M$ 住在权重里,需要一条突触;而 per-channel 要的是
同核内逐神经元的乘子,硬件只有 `leak_tau` 移位)。但 depthwise 1×1 的权重本就是逐通道的,
所以**每层多花一个核**或许能换到 8 位尾数的 per-channel 重标定 —— 那正是第五章要搜的
"核数换精度"权衡。**未验证的前提**:该核需"膜电位进、膜电位出",卷积能否作用于膜电位
输入待查。C10 的表述因此要分情况,不能写成绝对限制。

**两个后端 bug(同时挡住两条路线,修好是上游贡献)**

- `rg_build.py` 的 `build_groups`:一个 producer 分叉到 `RemapNode` 与 `CoreOpNode` 时,
  两个 successor 被放进同一个 set,而类型检查要求一 group 一类型 → 断言失败。
  我用投影跳连独立撞到同一处;他们的调查文档
  (`examples/quantize/cifar10/resnet/deploy_backendv2_investigation.md`)已定位到修法:
  按节点类型拆分 successor set。至少有两处 mixed set,不能特判。
- `op_node.py:587` 的 padding 去重:拿已归一化的 `new_node.raw_node.padding`
  (`[(1,1),(1,1)]`)比原始 `comp.padding`(`(1,1)`),**永远不等**,于是两个消费者要的
  padding 相同也被判冲突。三行可修。只在"一个产出被多个带 padding 的卷积消费"时触发,
  顺序网络不产生这种拓扑,残差是第一次踩到。

- [x] **实测 $\tau_l$ 判定规则** —— **已完成,并推翻了"per-channel 代价 8 倍"**
      折叠不是按层决定,而是**按折叠组**:`routing.py:652` 要求同组神经元的 Part 2 属性
      完全相同,任一逐神经元字段有差异即放弃折叠。`leak_tau` 在
      `NeuronParams.__vectorized_attrs__` 里,`attrs_part2(idx)` 按神经元下标取值
      (`op_node.py:413`),所以逐通道移位确实参与这个比较 —— 配置帧侧是正确的,
      不存在"折叠神经元共享一个 tau 而仿真按通道施加"的静默错配。

      于是代价取决于**折叠轴与通道轴是否正交**。卷积的折叠组沿空间展开,per-channel
      沿通道分 scale,两轴正交 ⇒ 组内 tau 恒定 ⇒ 折叠保留。实测(w8a8,conv 32-64 + fc 256):
      折叠成功次数 260 → 260 不变,神经元 SRAM 15174 → 15307 行(**+0.9%**),核数 24 → 24。
      SRAM 账:$n$ 个神经元折叠成一组占 $3 + \lceil (n-1)/4 \rceil$ 行,未折叠占 $2n$ 行(`neuron.py:99`)。

      **仍缺**:构造一个折叠组跨通道的用例,实测那条 8 倍分支真实存在(1 天)。

### P1.0 能力面补齐 —— 决定第五章有多少可搜内容

per-channel、per-group、ANN/SNN 模式三个维度都要做。它们当前都被挡住,而且

| 维度 | 硬件 | 后端 | 卡在哪 |
| --- | --- | --- | --- |
| per-channel | 支持(`leak_tau` 逐神经元移位) | 支持(`compile_to_paiir` 已通过) | ~~仿真器拒绝向量 `leak_tau`~~ **已打通**;但实测收益在噪声内,瓶颈转为"缺通道尺度离散的模型" |

## P1.5 — 两个 backendv2 bug(阻塞残差,且是能拿出去的上游贡献)

两条都**只在"一个产出被多个消费者分叉"时触发**,顺序网络不产生这种拓扑,
所以残差是第一次踩到。它们同时挡住我们和 `quantize` 分支的 ResNet。

- [ ] **`rg_build.py` 的 mixed successor set**(工作量未知,可能不小)
      `build_groups` 把一个节点的所有 successors 无条件放进同一个 set,而后续类型检查
      要求一个 group 只含一种节点(`RemapNode` / `CoreOpNode` / `InNode` / `OutNode`)。
      当 producer 同时接到 remap(padding 插入的)和 core 时断言失败:

      ```
      AssertionError: Expected exactly one non-empty node set for group building, but got:
      {'remap_node_set': {RemapNode(SequentialOp_0_Padded)},
       'routing_node_set': {CoreOpNode(AccumulateOp_0)}}
      ```

      我用投影跳连独立撞到同一处(`experiments/residual_probe.py`);他们的调查文档
      `examples/quantize/cifar10/resnet/deploy_backendv2_investigation.md` 已定位到修法:
      按节点类型拆分 successor set,或在连通分量构建时只合并同类节点。
      **至少有两处 mixed set,不能特判单个节点。**
